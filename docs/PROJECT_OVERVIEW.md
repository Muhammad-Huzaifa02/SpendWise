# SpendWise — Project Overview

## 1. Introduction

SpendWise is a personal expense management website developed as an academic Web Development project. Its purpose is to provide a structured interface for viewing expenses, planning budgets, and setting savings goals.

The first phase focuses on the website's structure and presentation using HTML5 and CSS3.

## 2. Problem statement

People may find it difficult to maintain a clear picture of their spending when expenses, budgets, and savings plans are tracked in separate places or informally. SpendWise explores how a single, organized interface can present these financial activities.

## 3. Project objectives

- Create a consistent multi-page website.
- Present financial summaries in a readable dashboard.
- Organize sample expenses by date, category, and payment method.
- Show category-based budget allocations.
- Present savings targets and progress.
- Use familiar Pakistan-oriented examples and conventions.
- Establish a foundation for future interactive functionality.

## 4. Intended users

The intended users are individuals who want to monitor personal spending, plan monthly budgets, and work towards savings targets. User registration and account management are not part of Phase 1.

## 5. Scope

### Included in Phase 1

- Eight linked HTML pages.
- Shared CSS stylesheet.
- Navigation and page layouts.
- Static summary cards, tables, progress bars, and sample forms.
- Basic browser-native form validation attributes where configured.
- Responsive CSS rules in the stylesheet.

### Excluded from Phase 1

- JavaScript behavior.
- User authentication and authorization.
- Backend services and APIs.
- Database integration.
- Saving, editing, or deleting financial records.
- Live calculations, dynamic filters, and working pagination.
- Payment processing or bank integrations.

## 6. Success criteria

The Phase 1 prototype is considered ready for review when all eight pages open, navigation works, shared styling loads, sample information is internally consistent, and the layouts remain usable at common desktop and mobile widths.

## 7. Future direction

Phase 2 is expected to add client-side interactions and validation. Later phases may introduce a backend, database, authentication, and secure financial record management. See [ROADMAP.md](ROADMAP.md).
